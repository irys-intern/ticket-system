# Ticket Categories

Categories help route tickets to the right person and make reporting meaningful. Choose the category that best fits the core issue, not the symptom.

## Bug

Something is broken — behavior that differs from how it is documented or clearly intended to work. If the user says "this used to work" or "this does the wrong thing," it is probably a bug.

Do not use this for performance problems unless they are severe and reproducible.

## Feature Request

The user wants something that does not exist yet. This includes new capabilities, changes to existing behavior, and integrations. Even if the request seems small, categorize it here so it reaches the product team.

## Support

The user needs help understanding or using something that works as designed. Examples: "how do I do X?", "where do I find Y?", account access questions, billing inquiries.

Most first-contact tickets start here. If the investigation reveals a bug, recategorize.

## Other

Use this only when none of the above fit. Add a comment explaining the nature of the ticket so it can be properly reviewed.
