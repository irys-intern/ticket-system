# Ticket Workflow

A ticket moves through a defined lifecycle. Your goal is to move it forward steadily without skipping steps.

## 1. Claim the Ticket

Browse open tickets and claim one that matches your expertise. Once claimed, the status becomes **In Progress** and you are responsible for it.

Do not claim more tickets than you can actively work. An unclaimed ticket moves faster than a claimed-but-ignored one.

## 2. Understand the Issue

Read the full description before responding. Look for:

- What the user expected vs. what happened
- Steps to reproduce (for bugs)
- Any files, screenshots, or error messages attached
- The priority and category — adjust them if they seem wrong

## 3. Respond or Investigate

If you can resolve the issue immediately, do so and move to step 4.

If you need more information, ask for it and set the status to **Waiting for Response**.

If investigation will take time, tell the user what you are doing and when to expect an update.

## 4. Resolve

Once the issue is addressed, set the status to **Resolved**. Send a clear summary of what was done and what, if anything, the user needs to do on their end.

You may also use this step to send a satisfaction survey or request confirmation that the issue is fully resolved.

## 5. Close

After the user confirms resolution — or after a reasonable waiting period with no reply — close the ticket.

Closed tickets cannot be commented on or edited. If the user reopens the same issue after closure, ask them to submit a new ticket and reference the closed one.

---

## Key Rules

- Never leave a ticket in a status that does not reflect reality.
- If you are waiting on someone internally, the status is still **In Progress**, not **Waiting for Response** (that status is only for waiting on the user).
- Update the status every time it changes, not in batches.
