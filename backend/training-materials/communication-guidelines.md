# Communication Guidelines

Every comment you write is a message to a real person. Keep it clear, honest, and professional.

## First Response

Always acknowledge the issue before doing anything else. The user should know you have read and understood their problem.

Good:
> Thanks for reaching out. I can see that X is not behaving as expected — I'll investigate and follow up shortly.

Avoid:
> Got it.

## Asking for Information

Ask for everything you need in one comment. Going back and forth for basic details frustrates users and slows resolution.

Before responding, check the ticket description carefully. Do not ask for information the user has already provided.

## Setting Expectations

If a resolution will take time, say so. Vague timelines are worse than honest ones.

Good:
> This will require input from the engineering team. I expect to have an update for you by end of day tomorrow.

Avoid:
> We are looking into it.

## Delivering Bad News

Be direct. If something cannot be done, say so clearly and explain why when you can. Offer alternatives if any exist.

## Tone

- Use plain language. Avoid jargon unless the user is clearly technical.
- Do not over-apologize. One acknowledgment is enough.
- Do not be dismissive or defensive, even if the user is frustrated.
- Match the user's level of formality roughly, but always stay professional.

## Internal vs. User-Facing Notes

All comments in this system are visible to the user. Do not write anything in a comment that you would not say directly to them.
